## 3.22 剧本评审与修复：问题卡 + 意见先核验 + 改坏了就回退【外部·可直接用】

**用法**：剧本要评审、要按意见改稿时用。它把“评审”和“修改”分成两个角色：先评后修，评审只给有原文证据的问题卡，修改前先核对每条意见在当前版本是否还成立，改完检查有没有改坏（逻辑顺了但人物平了、笑点和压迫感没了等）。适合编剧组收到多方修改意见、意见互相打架时用。和 3.16（问题五栏卡）的区别：3.16 是一张卡怎么写，这条管整个“评审—核验—修复—回退”的流程。

**来源**：[short-drama-factory](https://github.com/lixiaoxiao9888-create/short-drama-factory) references/script-doctor-protocol.md，MIT（收集人提供，11/06 继续深挖）。摘编：去掉了机检编号，“红果档位”相关的部分保留了通用判据。

**提示词正文**：

```
请按“先评后修”处理下面的剧本。评审和修改分开输出：评审报告里不夹带改好的正文，修改交付里不夹带长篇自评。

【一、两个角色】
- 评审官：判断这稿是否兑现了约定的观看体验，给出可以核对的问题和修订目标；不代替作者改稿（除非我明确要改）。
- 修复器：在授权范围内做最小足够的改动，交付可以直接替换的完整稿；不擅自扩大范围、不重写未授权部分、不“顺手美化”。

【二、评审强度（我会指定，没指定用快审）】
- 快审：只读指定范围，给 3~5 条最影响观看的问题 + 必须保留的长板。
- 专项：只查某一项（对白 / 断章 / 连续性 / 付费卡点），其他维度标“未测”。
- 终审：通读约定范围，给完整维度状态和没读到的部分。读不完就说读不完，不宣称完整通过。

【三、问题卡】
编号（同一根因合并成一条）｜范围（第几集第几场）｜按影响定级｜证据（逐字短原文）｜观察到什么｜为什么损害目标｜想改善的观众体验（写体验，不写“把第 3 句改成……”）｜必须保住的现有长处｜允许的改动范围｜连带要复查什么｜状态（待处理 / 已解决 / 已否决 / 待核）
证据必须逐字核对原文；找不到支撑就标“待核”，不凑问题数量。

【四、按影响定级】
- 阻断：核心观看承诺失败——胜负看不懂、结局靠无来源信息成立、全篇对白难懂、约定的核心情绪始终没发生、该断章的地方没有钩子。
- 重大：重要段落或反复出现的问题明显削弱体验，例如一整集攻防原地打转、主角的结果不是自己争来的。
- 局部：单场信息复述、称呼不统一、某句台词不符合身份。
单一关键错误也可以是阻断；次数多不等于阻断；任何关键失败不能被其他长处抵消。不输出总分和爆款预测。

【五、修改前先核验意见】
修复器拿到问题卡，第一件事是核对它在当前版本是否成立。以下情况尤其要复核：意见来自旧版本；没有引原文；把直说、沉默、有依据的次优选择一律判差；没说明适用条件；意见的前提已经被正文满足。
每条意见四选一：采纳 / 部分采纳 / 否决 / 待核，并简述理由。审稿人的审美偏好不是命令，直白还是留白、强爽还是温情，按项目目标判断。

【六、修复纪律】
1. 先读要改的段落和前后依赖，明确要改善什么、必须保留什么。
2. 选够用的修复层级：表达 → 场景 → 单集 → 核心关系 → 单元重构。局部补丁解决不了就回上游整段重写，但能微调就微调。
3. 优先替换，确实缺了才补；先删重复说明、重复证明同一种情绪的段落。
4. 修了某一句，扫一遍同一集里所有同类问题。

【七、改坏了就回退】出现任一项，回滚或换写法：逻辑更顺了，但人物更平了；笑点、压迫感、亲密感、缺陷或余味消失了；情绪被提前解决了；风格化的完整句被改成统一的碎句；为了过检查而注水或删掉必要过程。
同一个问题连续两次修改没有改善，就换写法、缩小范围或回到上游构思，不无限循环，也不假称通过。

【交付】评审：结论与最大影响 → 必须保留的长处 → 按优先级排列的问题卡 → 下一步。修改：完整替换稿 + 每条意见的处置结果。
```
